# Deploy Fixnest

## Render API

Create a Render Blueprint from this repository using the root `render.yaml`, or create a Node Web Service with root directory `server`, build command `npm ci`, and start command `npm start`.

Set these Render environment values:

- `MONGO_URI`: MongoDB Atlas connection string for a dedicated database user. Rotate any password shared outside the hosting secret manager before using it.
- `CLIENT_URL`: exact Vercel production origin, such as `https://fixnest.vercel.app`.
- `ADMIN_EMAIL`: `sudakshina2003@gmail.com`.
- `ADMIN_PASSWORD_HASH`: bcrypt hash for the admin password.
- `JWT_SECRET`: generated by the Render Blueprint; keep it private.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`: configure a mail provider to enable OTP delivery.

The API health endpoint is `/api/health`; it returns success only after MongoDB connects. Admin login still requires email OTP, so configure SMTP before launch.

## Vercel frontend

Import the repository as a Vercel project with root directory `client`, build command `npm run build`, and output directory `dist`. Set `VITE_API_URL` to `https://<render-service>.onrender.com/api` and redeploy. The `client/vercel.json` rewrite supports direct React Router paths.

After deployment, verify the Vercel app can load services from Render. If browser API requests fail, check that Render's `CLIENT_URL` exactly matches the Vercel origin and that Atlas allows the Render service to connect.
